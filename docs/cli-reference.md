# Command-line reference

Every option, environment variable, and exit status of `cleaner`. The man page (`man cleaner`) carries the same reference.

## Options

- **`-c, --config FILE`**: Use a custom configuration file instead of the default discovery order.
- **`-d, --dry-run`**: Preview potential space savings without deleting anything (default). A text preview that found something to clean ends with a `Next:` line, unless `--min-reclaim` or `--min-free` would skip the cleanup; then it ends with that skip note instead. A bare preview names `cleaner --clean`. When the preview used an explicit `--config`, a non-default or environment-overridden `--risk`, `--trash`, `--exclude`, `--exclude-from`, `--only-target`, `--only-target-exact`, `--exclude-target`, `--exclude-target-exact`, `--only-path`, `--exclude-path`, `--skip-actions`, `--no-sudo`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--trash-keep-days`, `--trash-max-size`, `--fail-fast`, or `--action-timeout` (from the command line or their environment variables), the next line prints the full apply command with those options, each value quoted with `printf %q`, so it applies the same plan. `--quiet` and `--json` print no `Next:` line.
- **`--clean`**: Enable cleanup with a single summary confirmation prompt. Cleanup is also enabled by `-f/--force`, `-i/--interactive`, or a truthy `LINUX_CLEANER_FORCE` (the last of `--dry-run` or a cleanup flag decides between preview and cleanup; `--clean` does not undo an earlier `--force` or `--interactive`). When `flock(1)` is available, mutating runs (`--clean`/`--force`/`--interactive`, `--restore`, `--purge-sessions`, `--hold-session`, and `--release-session`) acquire an exclusive lock on `~/.cache/linux-cleaner/cleaner.lock` (directory created mode `0700`, refusing symlinks). Default `--lock-wait 0` fails immediately with exit `1` on contention; a positive wait opts in to bounded acquisition and requires `flock`. Dry-run and read-only modes never take the lock.
- **`-i, --interactive`**: Enable cleanup and prompt before cleaning each target individually (overrides an earlier `-f/--force` or `LINUX_CLEANER_FORCE`; `--clean` does not clear it).
- **`-f, --force`**: Enable cleanup and skip confirmation prompts (except `danger` targets and non-forced session purges; overrides an earlier `-i/--interactive`, and `--clean` does not clear it).
- **`--yes-danger`**: Bypass the manual confirmation prompt for `danger` targets.
- **`-t, --trash`**: Move cleaned files into a restorable quarantine session under `~/.cache/linux-cleaner/quarantine/<timestamp>/` instead of deleting permanently (with `--init-env`, enable `LINUX_CLEANER_TRASH=1` and `LINUX_CLEANER_TRASH_KEEP_DAYS=30` in the created timer env file). Passing `--trash` alone keeps dry-run preview mode. Each target records one `UID`/`GID` pair in `quarantine.meta`, applied best-effort on restore (mixed ownership inside a tree is not preserved). When a target sits on a different filesystem from `~/.cache/linux-cleaner/quarantine`, the cleaner checks available space there before moving and refuses the target if its planned size exceeds free space, leaving it in place (same-filesystem moves are renames and need no check).
- **`-r, --risk LEVEL`**: Maximum risk level to process: `safe`, `medium`, or `danger` (default: `safe`).
- **`-e, --exclude PATTERNS`**: Comma-separated `find` glob/path patterns to exclude globally (e.g. `.git,*.log`). Verify exclusions with `--dry-run` first.
- **`--exclude-from FILE`**: With cleanup, read literal exclusion glob/path patterns from `FILE`, one per line (horizontal whitespace trimmed; blank lines and `#`-prefixed trimmed lines ignored; literal commas preserved; trailing slashes normalized like `--exclude`). Adds to `-e/--exclude` and per-target `exclude:` rows. Last occurrence wins and overrides `LINUX_CLEANER_EXCLUDE_FROM` (unset/empty means no file; non-cleanup modes ignore the environment variable). Fails closed pre-lock on missing, directory, non-regular, unreadable, or CR-containing inputs. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--only-target PATTERN`**: With cleanup or `--list-targets`, process only targets whose `NAME` contains `PATTERN` (case-sensitive literal substring match; `PATTERN` may be a comma-separated list: a target matches when its `NAME` contains any listed substring, and empty entries are rejected); exits `1` if none match. Cannot be combined with `--only-target-exact`, `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--only-target-exact NAME`**: With cleanup or `--list-targets`, process only targets whose `NAME` exactly equals literal `NAME` (case-sensitive literal equality with no comma splitting or glob matching; last occurrence wins and overrides both `LINUX_CLEANER_ONLY_TARGET_EXACT` and `LINUX_CLEANER_ONLY_TARGET`); exits `1` if none match. Cannot be combined with `--only-target`, `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--exclude-target PATTERN`**: With cleanup or `--list-targets`, skip targets whose `NAME` contains `PATTERN` (case-sensitive literal substring match; `PATTERN` may be a comma-separated list: a target matches when its `NAME` contains any listed substring, and empty entries are rejected); exits `1` if no targets remain. Cannot be combined with `--exclude-target-exact`, `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--exclude-target-exact NAME`**: With cleanup or `--list-targets`, skip targets whose `NAME` exactly equals literal `NAME` (case-sensitive literal equality with no comma splitting or glob matching; last occurrence wins and overrides both `LINUX_CLEANER_EXCLUDE_TARGET_EXACT` and `LINUX_CLEANER_EXCLUDE_TARGET`); exits `1` if no targets remain. Cannot be combined with `--exclude-target`, `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--only-path PATH`**: With cleanup or `--list-targets`, select ordinary targets whose physical path equals or lies below one existing absolute literal `PATH` (whole path components; `/` selects every eligible resolved target). The last occurrence wins and overrides `LINUX_CLEANER_ONLY_PATH`; unset or empty environment input means no scope. The effective path is literal, without placeholder expansion. NAME filters apply first, then PATH selection, then cleanup risk and safety guards. All `action:*` rows are excluded because their effects may extend beyond the scope. Missing/unresolvable candidates and expanded or physical paths containing line feeds are ineligible; an invalid scope exits `1`, and existing NAME-selection errors take precedence over no eligible PATH matches. Inventory keeps configured paths and includes all risks without analysis. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, `--doctor`, `--trash-keep-days`, or `--trash-max-size` (including their environment mirrors).
- **`--exclude-path PATH`**: With cleanup or `--list-targets`, skip targets whose resolved physical or expanded literal path equals, lies below, or contains one existing absolute literal `PATH` (whole path components; `action:*` rows are excluded when their path matches; missing targets that do not match literally are never excluded). The last occurrence wins and overrides `LINUX_CLEANER_EXCLUDE_PATH`; unset or empty environment input means no exclusion. Exits `1` if `PATH` is not a literal absolute path without line feeds, does not resolve to an existing path, or removes every remaining target (`Error: --exclude-path <PATH> left no config targets to process.`). Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--skip-actions`**: With cleanup or `--list-targets`, exclude all `action:*` rows before risk-hiding counts, sizing, and command/root probes while retaining ordinary paths (including `filter:cxx_build`) and global retention (`--trash-keep-days`, `--trash-max-size`). Skipped actions do not appear in JSON `hidden_by_risk` and never invoke external package-manager commands; exits `1` if no targets remain (`Error: --skip-actions left no config targets to process.`). Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--no-sudo`**: With cleanup, dry-run preview, or `--restore`, suppress all `sudo` probes (`sudo -n`), cached-credential escalation, and interactive `sudo -v` password prompts, even when a controlling terminal or passwordless `sudo` exists. Targets requiring root privileges skip cleanly (`requires root`), privileged (`use_sudo=true`) quarantine records fail cleanly while keeping unprivileged sibling restores working, and dry-run `Next:` replays `--no-sudo`. Set by a truthy `LINUX_CLEANER_NO_SUDO`; non-cleanup/non-restore modes ignore the environment variable. Cannot be combined with `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--lock-wait SECONDS`**: Wait up to a literal decimal `0..2147483647` seconds for the existing exclusive lock on cleanup, restore or purge. Default `0` retains immediate contention failure and permits missing `flock`; positive values require `flock` and exit `1` on acquisition failure before target/session/report/log effects. Leading zeros are normalized. Dry-run, inventories, report, check-config, init-config, init-env and doctor do not lock or wait. Last CLI value overrides the environment, even malformed inherited input; missing/empty CLI values and invalid effective values fail before initialization or state creation.
- **`--min-reclaim SIZE`**: With cleanup, skip the run when the planned reclaimable total is below `SIZE` (an integer with an optional `K`, `M`, `G`, or `T` 1024-based unit, e.g. `500M` or `2G`). User-level prune actions (`uv`/`pnpm`/`hf`/`nix-store`) are sized at run time and do not count toward the threshold. In `--dry-run` mode, prints a note when a cleanup run would skip; in a cleanup run, prints why nothing was cleaned, records `Result: skipped below --min-reclaim SIZE` in `last-report.txt`, and exits `0`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--min-free SIZE`**: With cleanup, skip the run when the selected filesystem (default: `HOME`) already has at least `SIZE` free (an integer with an optional `K`, `M`, `G`, or `T` 1024-based unit, e.g. `10G`; `0` disables the check). When free space cannot be read, it prints a warning and the run proceeds as without `--min-free`. In `--dry-run` mode, prints a note when a cleanup run would skip; in a cleanup run, prints why nothing was cleaned, records `Result: skipped at or above --min-free SIZE` in `last-report.txt`, and exits `0`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--min-free-path PATH`**: Select the filesystem measured by `--min-free` using an absolute existing file or directory. Requires `--min-free` or `LINUX_CLEANER_MIN_FREE`; missing thresholds, relative paths, or nonexistent paths exit `1`. Defaults to `HOME` when unset; CLI overrides `LINUX_CLEANER_MIN_FREE_PATH`. A failed free-space probe warns and cleanup proceeds. This only selects the pressure probe, not cleanup targets. Dry-run `Next:` commands carry both options; JSON `would_skip` and `--exit-code` use the same gate. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--min-age DAYS`**: With cleanup, raise every ordinary target's `MIN_AGE_DAYS` threshold to at least `DAYS` days (a non-negative decimal integer) for that run. Targets configured with a larger `MIN_AGE_DAYS` keep their configured threshold, `filter:cxx_build` rows use the raised value as their idle threshold, and `action:*` rows are skipped because external commands cannot apply a file-age filter. Exits `1` on a malformed `DAYS` or when no eligible config target remains after skipping `action:*` rows. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--action-timeout SECONDS`**: With cleanup, stop each `action:*` command still running after `SECONDS` seconds (a non-negative decimal integer) with `timeout --kill-after=10`, print `Error: Action '<action>' for '<name>' timed out after SECONDS seconds.`, count the target as failed, and continue with the remaining targets and retention, so the run exits `1`. `0` or unset keeps actions unbounded; a positive limit in a cleanup run requires `timeout(1)`. Exits `1` on a malformed `SECONDS`. On a terminal the action runs in the foreground so Ctrl-C still reaches it; a timeout then signals only the action's own process (sudo passes it on), so a helper process the action started itself may outlive the limit. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--trash-keep-days DAYS`**: With cleanup, purge quarantine sessions older than `DAYS` days (a non-negative integer) at the end of a non-dry-run cleanup via `older-than:DAYS` retention (prompts for confirmation unless `-f/--force` is set, and exits `0` when no sessions match). A `--dry-run` purges nothing. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, `--doctor`, or `--only-path`.
- **`--trash-max-size SIZE`**: With cleanup, purge the oldest quarantine sessions beyond a total byte budget of `SIZE` (same integer and optional `K`/`M`/`G`/`T` 1024-based unit grammar as `--min-reclaim`) at the end of a non-dry-run cleanup via `max-size:SIZE` retention (running after `--trash-keep-days` if both are set; prompts for confirmation unless `-f/--force` is set, and exits `0` when within budget). Held sessions still count toward `SIZE` and are skipped. A `--dry-run` purges nothing. Overridden by CLI over `LINUX_CLEANER_TRASH_MAX_SIZE`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, `--doctor`, or `--only-path`.
- **`--list-targets`**: List configured targets (`NAME`, `risk`, `path`, `description`) without disk analysis. Supports `--only-target`, `--only-target-exact`, `--exclude-target`, `--exclude-target-exact`, `--only-path`, `--exclude-path`, and `--skip-actions` with the same selection and empty-selection errors as cleanup; inventory includes all risk levels. Read-only; requires a config file. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--check-config`**: Validate config syntax and exit without disk analysis. Prints `OK: N targets in <path>`. With `--json`, emits one machine-readable JSON validation summary (`valid`, `status`, `config_file`, `source`, `targets_count`, `protect_count`, `include_files`, `searched`, `error`, `error_file`, and `error_line`) instead of plain text or stderr diagnostics while preserving exit `0`/`1` status. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--init-config`**: Copy the active config to `${XDG_CONFIG_HOME:-$HOME/.config}/linux-cleaner/cleaner.conf` (mode `0644`, never overwriting an existing file or following symlinks) and exit. Add `--overlay` to write a minimal `include|<canonical-source>` overlay instead of copying every default row. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-env`, `--doctor`, `--exclude-from`, `--only-target`, `--only-target-exact`, `--exclude-target`, `--exclude-target-exact`, `--only-path`, `--exclude-path`, `--skip-actions`, `--no-sudo`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--trash-max-size`, `--notify`, `--fail-fast`, or `--json`.
- **`--overlay`**: With `--init-config`, scaffold a thin user overlay at `${XDG_CONFIG_HOME:-$HOME/.config}/linux-cleaner/cleaner.conf` containing `include|<canonical-source>` plus commented `protect|` and custom-target examples so packaged defaults update automatically without editing a full copy. Uses the same mode `0644`, symlink refusal, and never-overwrite rules; exits `1` without `--init-config` or when the canonicalized source path cannot be represented safely in `include|PATH`.
- **`--init-env`**: Copy the shipped systemd timer environment template (`linux-cleaner.env.example`) to `$HOME/.config/linux-cleaner/env` (mode `0644`, never overwriting an existing file or following symlinks; ignores `XDG_CONFIG_HOME` to match systemd's `EnvironmentFile=-%h/.config/linux-cleaner/env`) and exit without requiring `cleaner.conf`. With `-t`/`--trash`, also enable `LINUX_CLEANER_TRASH=1` and `LINUX_CLEANER_TRASH_KEEP_DAYS=30` in the staged copy before publishing (failing closed if the template sets conflicting active values), while keeping bare `--init-env` unaffected by ambient `LINUX_CLEANER_TRASH`. Searches checkout `examples/linux-cleaner.env.example`, staged/installed `../share/linux-cleaner/linux-cleaner.env.example`, `/usr/local/share/linux-cleaner/linux-cleaner.env.example`, and `/usr/share/linux-cleaner/linux-cleaner.env.example`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--overlay`, `--doctor`, `--exclude-from`, `--only-target`, `--only-target-exact`, `--exclude-target`, `--exclude-target-exact`, `--only-path`, `--exclude-path`, `--skip-actions`, `--no-sudo`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--trash-max-size`, `--notify`, `--fail-fast`, or `--json`.
- **`--doctor`**: Print a read-only environment checklist (`OK`/`WARN`/`INFO` lines for the resolved configuration path and whether it came from `XDG`, `/etc`, `checkout`, or `explicit`, `check_gnu_userland`, `pgrep`, `flock`, `git`, non-interactive `sudo -n`, `notify-send`, `systemctl --user is-enabled` for the `clean`/`retention`/`monitor` timers, the last cleanup outcome, a `WARN` when the enabled clean timer's `~/.config/linux-cleaner/env` sets `LINUX_CLEANER_TRASH` with neither `LINUX_CLEANER_TRASH_KEEP_DAYS`, valid `LINUX_CLEANER_TRASH_MAX_SIZE`, nor an enabled retention timer, a `WARN` when `~/.config/linux-cleaner/monitor.env` is unreadable or sets `LINUX_CLEANER_ONLY_PATH` with `LINUX_CLEANER_TRASH_KEEP_DAYS` or `LINUX_CLEANER_TRASH_MAX_SIZE`, and the quarantine session count). Immediately after the timers, prints `INFO: last cleanup: <Saved> <Result>` using the header values from `${XDG_STATE_HOME:-$HOME/.local/state}/linux-cleaner/last-report.txt`, or `INFO: last cleanup: none recorded` when absent; symlinked reports or `linux-cleaner` state directories are not followed. Uses `WARN` when the result has `failed>0`, an `Interrupted:` line is present, a `Retention failed: true` line is present (appending `; retention failed`), or the clean timer is enabled and the report's modification time is more than two days old. An unreadable report prints `WARN: last cleanup: report not readable`. Last-cleanup warnings do not change the exit status. When the clean timer is enabled, also prints `INFO: daily timer plan: risk=<value|safe> deletion=<quarantine|permanent> keep-days=<N|none> [max-size=<SIZE>] [config=<path>] (<env path|no env file>)` from `~/.config/linux-cleaner/env`; without an env file it shows `risk=safe deletion=permanent keep-days=none (no env file)`. `max-size=` appears when `LINUX_CLEANER_TRASH_MAX_SIZE` is set, and `config=` appears when the env file sets `LINUX_CLEANER_CONFIG`. The line uses `WARN` and appends `; invalid risk` when the env risk is not `safe`, `medium`, `danger` or `dangerous` (in any case), `; invalid keep-days` when `LINUX_CLEANER_TRASH_KEEP_DAYS` is not a non-negative integer, `; invalid trash-max-size` when `LINUX_CLEANER_TRASH_MAX_SIZE` is not a valid size, `; config not readable` when that config is not a readable file, `; config invalid` when it fails the schema check, `; only-path with keep-days` when the file sets both `LINUX_CLEANER_ONLY_PATH` and `LINUX_CLEANER_TRASH_KEEP_DAYS`, `; only-path with trash-max-size` when it sets both `LINUX_CLEANER_ONLY_PATH` and `LINUX_CLEANER_TRASH_MAX_SIZE`, `; invalid min-reclaim` when `LINUX_CLEANER_MIN_RECLAIM` is not a valid size, `; invalid min-free` when `LINUX_CLEANER_MIN_FREE` is not a valid size, `; min-free-path without min-free` when `LINUX_CLEANER_MIN_FREE_PATH` is set without `LINUX_CLEANER_MIN_FREE`, `; invalid min-free-path` when `LINUX_CLEANER_MIN_FREE_PATH` is not a literal absolute path without line feeds, `; invalid min-age` when `LINUX_CLEANER_MIN_AGE` is not a non-negative integer, `; invalid action-timeout` when `LINUX_CLEANER_ACTION_TIMEOUT` is not a non-negative integer, `; invalid lock-wait` when `LINUX_CLEANER_LOCK_WAIT` is not an integer from `0` to `2147483647`, `; log-max-size without log` when `LINUX_CLEANER_LOG_MAX_SIZE` is set without `LINUX_CLEANER_LOG`, or `; invalid log-max-size` when `LINUX_CLEANER_LOG_MAX_SIZE` is not a valid size, all of which the clean run refuses. A relative `LINUX_CLEANER_CONFIG` is checked under `HOME`, where the user service starts; values are trimmed of surrounding whitespace, as systemd does. An env file that exists but cannot be read prints `WARN: daily timer plan: env file not readable (<path>)`, because systemd then fails every timer run. Disabled timers print no plan line. The retention warning and exit status are unchanged. A readable file is schema-checked; an invalid file prints `WARN: config: <path> (<source>, <error>)` and the rest of the checklist still prints. Exit `0` when cleanup can run (and, with `--strict`, no warnings are present) or `1` when the configuration file is missing, unreadable, or invalid, GNU userland is missing, or `--strict` observes one or more warnings. Requires no configuration file to print the checklist. With `--json`, emit a machine-readable JSON summary instead of plain text. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, `--exclude-from`, `--only-target`, `--only-target-exact`, `--exclude-target`, `--exclude-target-exact`, `--only-path`, `--exclude-path`, `--skip-actions`, `--no-sudo`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--trash-max-size`, `--notify`, or `--fail-fast`.
- **`--strict`**: With `--doctor`, fail with exit status `1` (and emit `"ready": false` and `"exit_code": 1` under `--json`) whenever any diagnostic `WARN` is emitted (such as unbounded quarantine retention, scheduler env problems, `monitor.env` conflicts/unreadable files, failed/interrupted/stale last cleanup reports, missing helper binaries like `pgrep`/`flock`/`git`, or a symlinked/unreadable quarantine directory); informational `INFO:` notes such as missing `notify-send` or unavailable `sudo -n` do not fail `--strict`. Exits `1` if given without `--doctor`. CLI-only, with no environment mirror.
- **`--list-sessions`**: List quarantine sessions (timestamp, size, date, and each item's `full`/`aged` type and original path). Human output warns when immediate entries lack metadata accounting. JSON adds integer `unrecorded_entry_count` to every session, including zero; the `.hold` marker is not counted. A session protected by `--hold-session` ends its human line with `held`, and JSON `held` is `true` for it (`false` otherwise). Read/enumeration errors fail inventory and block purge before confirmation or deletion, including forced or inline retention. Counts are informational; zero does not certify metadata integrity, recoverability or safe purge. Read-only; requires no config file. Cannot be combined with `--restore`, `--purge-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.
- **`--restore SESSION`**: Restore files from a quarantine session (`latest` or an immediate child timestamp directory name; `/` and `.`/`..` are rejected). Add `--dry-run` to preview selected records without taking the lock, invoking sudo, or changing payload, logs, metadata or session mtime. Prints `would restore`, `conflict`, `already restored`, `missing`, `unknown type`, or `invalid record` (the last two are records the real restore skips as failed), followed by two spaces and the original path; ends with `Dry-run: nothing restored.` and exits `0` even for conflicts, missing payload, or invalid records. Add `--json` alongside an active explicit `--dry-run` (without `--clean`/`--force`/`--interactive` override) to emit one JSON preview (`session`, `session_mtime`, `held`, `selector`, `selector_mode`, `records`, and `counts`); mutating restores still reject `--json`. Honours `--only` and `--only-exact`; an unmatched selector still exits `1`. Probes use the current user's access and do not guarantee permissions or free space for a later restore. Cannot be combined with `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--init-env`, or `--doctor`.

## Exit status

With **`--exit-code`**, a text or JSON cleanup dry run returns **`2`** when cleanup would run, or **`0`** when a minimum-reclaim/free gate would skip it or there is nothing to clean; errors remain **`1`**. Without this modifier, successful previews return **`0`**.

Returns **`0`** on success, **`130` (`SIGINT`)** or **`143` (`SIGTERM`)** when a cleanup is interrupted by a signal, and **`1` (non-zero)** on a configuration/usage error, failure to acquire the mutation lock within the configured wait (default zero), including a concurrent mutating run holding `~/.cache/linux-cleaner/cleaner.lock` (`Error: another linux-cleaner run is in progress (lock: <path>).`), or a **failed operation** (an attempted delete, quarantine move, predefined action, restore, or session purge that did not succeed). When an operation fails during cleanup, `cleaner` reports the error on stderr, continues processing remaining targets, and exits `1`.

A **skip is not a failure** and exits **`0`**: a declined `danger` target, a target blocked by a running process, an `UNSAFE` or `protected` path, a git-tracked target, a root-requiring target when privileges are unavailable, or a predefined `action:*` whose package manager binary is not installed.
