# Command-line reference

Every option, environment variable, and exit status of `cleaner`. The man page (`man cleaner`) carries the same reference.

## Options

- **`-c, --config FILE`**: Use a custom configuration file instead of the default discovery order.
- **`-d, --dry-run`**: Preview potential space savings without deleting anything (default). A text preview that found something to clean ends with a `Next:` line. A bare preview names `cleaner --clean`. When the preview used an explicit config, a risk above `safe`, `--trash`, `--exclude`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--min-free`, `--min-free-path`, `--min-age`, or `--trash-keep-days` (from the command line or their environment variables), the next line prints the full apply command with those options, each value quoted with `printf %q`, so it applies the same plan. `--quiet` and `--json` print no `Next:` line.
- **`--clean`**: Enable cleanup with a single summary confirmation prompt. Cleanup is also enabled by `-f/--force`, `-i/--interactive`, or a truthy `LINUX_CLEANER_FORCE` (the last of `--dry-run` or a cleanup flag decides between preview and cleanup; `--clean` does not undo an earlier `--force` or `--interactive`). When `flock(1)` is available, mutating runs (`--clean`/`--force`/`--interactive`, `--restore`, and `--purge-sessions`) acquire an exclusive lock on `~/.cache/linux-cleaner/cleaner.lock` (directory created mode `0700`, refusing symlinks). Default `--lock-wait 0` fails immediately with exit `1` on contention; a positive wait opts in to bounded acquisition and requires `flock`. Dry-run and read-only modes never take the lock.
- **`-i, --interactive`**: Enable cleanup and prompt before cleaning each target individually.
- **`-f, --force`**: Enable cleanup and skip confirmation prompts (except `danger` targets and non-forced session purges).
- **`--yes-danger`**: Bypass the manual confirmation prompt for `danger` targets.
- **`-t, --trash`**: Move cleaned files into a restorable quarantine session under `~/.cache/linux-cleaner/quarantine/<timestamp>/` instead of deleting permanently. Passing `--trash` alone keeps dry-run preview mode. Each target records one `UID`/`GID` pair in `quarantine.meta`, applied best-effort on restore (mixed ownership inside a tree is not preserved). When a target sits on a different filesystem from `~/.cache/linux-cleaner/quarantine`, the cleaner checks available space there before moving and refuses the target if its planned size exceeds free space, leaving it in place (same-filesystem moves are renames and need no check).
- **`-r, --risk LEVEL`**: Maximum risk level to process: `safe`, `medium`, or `danger` (default: `safe`).
- **`-e, --exclude PATTERNS`**: Comma-separated `find` glob/path patterns to exclude globally (e.g. `.git,*.log`). Verify exclusions with `--dry-run` first.
- **`--only-target PATTERN`**: With cleanup or `--list-targets`, process only targets whose `NAME` contains `PATTERN` (case-sensitive literal substring match; `PATTERN` may be a comma-separated list: a target matches when its `NAME` contains any listed substring, and empty entries are rejected); exits `1` if none match. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--exclude-target PATTERN`**: With cleanup or `--list-targets`, skip targets whose `NAME` contains `PATTERN` (case-sensitive literal substring match; `PATTERN` may be a comma-separated list: a target matches when its `NAME` contains any listed substring, and empty entries are rejected); exits `1` if no targets remain. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--only-path PATH`**: With cleanup or `--list-targets`, select ordinary targets whose physical path equals or lies below one existing absolute literal `PATH` (whole path components; `/` selects every eligible resolved target). The last occurrence wins and overrides `LINUX_CLEANER_ONLY_PATH`; unset or empty environment input means no scope. The effective path is literal, without placeholder expansion. NAME filters apply first, then PATH selection, then cleanup risk and safety guards. All `action:*` rows are excluded because their effects may extend beyond the scope. Missing/unresolvable candidates and expanded or physical paths containing line feeds are ineligible; an invalid scope exits `1`, and existing NAME-selection errors take precedence over no eligible PATH matches. Inventory keeps configured paths and includes all risks without analysis. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--doctor`, or `--trash-keep-days` (including its environment mirror).
- **`--exclude-path PATH`**: With cleanup or `--list-targets`, skip targets whose resolved physical or expanded literal path equals, lies below, or contains one existing absolute literal `PATH` (whole path components; `action:*` rows are excluded when their path matches; missing targets that do not match literally are never excluded). The last occurrence wins and overrides `LINUX_CLEANER_EXCLUDE_PATH`; unset or empty environment input means no exclusion. Exits `1` if `PATH` is not a literal absolute path without line feeds, does not resolve to an existing path, or removes every remaining target (`Error: --exclude-path <PATH> left no config targets to process.`). Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--lock-wait SECONDS`**: Wait up to a literal decimal `0..2147483647` seconds for the existing exclusive lock on cleanup, restore or purge. Default `0` retains immediate contention failure and permits missing `flock`; positive values require `flock` and exit `1` on acquisition failure before target/session/report/log effects. Leading zeros are normalized. Dry-run, inventories, report, check-config, init-config and doctor do not lock or wait. Last CLI value overrides the environment, even malformed inherited input; missing/empty CLI values and invalid effective values fail before initialization or state creation.
- **`--min-reclaim SIZE`**: With cleanup, skip the run when the planned reclaimable total is below `SIZE` (an integer with an optional `K`, `M`, `G`, or `T` 1024-based unit, e.g. `500M` or `2G`). User-level prune actions (`uv`/`pnpm`/`hf`/`nix-store`) are sized at run time and do not count toward the threshold. In `--dry-run` mode, prints a note when a cleanup run would skip; in a cleanup run, prints why nothing was cleaned, records `Result: skipped below --min-reclaim SIZE` in `last-report.txt`, and exits `0`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--min-free SIZE`**: With cleanup, skip the run when the selected filesystem (default: `HOME`) already has at least `SIZE` free (an integer with an optional `K`, `M`, `G`, or `T` 1024-based unit, e.g. `10G`; `0` disables the check). When free space cannot be read, it prints a warning and the run proceeds as without `--min-free`. In `--dry-run` mode, prints a note when a cleanup run would skip; in a cleanup run, prints why nothing was cleaned, records `Result: skipped at or above --min-free SIZE` in `last-report.txt`, and exits `0`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--min-free-path PATH`**: Select the filesystem measured by `--min-free` using an absolute existing file or directory. Requires `--min-free` or `LINUX_CLEANER_MIN_FREE`; missing thresholds, relative paths, or nonexistent paths exit `1`. Defaults to `HOME` when unset; CLI overrides `LINUX_CLEANER_MIN_FREE_PATH`. A failed free-space probe warns and cleanup proceeds. This only selects the pressure probe, not cleanup targets. Dry-run `Next:` commands carry both options; JSON `would_skip` and `--exit-code` use the same gate. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--min-age DAYS`**: With cleanup, raise every ordinary target's `MIN_AGE_DAYS` threshold to at least `DAYS` days (a non-negative decimal integer) for that run. Targets configured with a larger `MIN_AGE_DAYS` keep their configured threshold, `filter:cxx_build` rows use the raised value as their idle threshold, and `action:*` rows are skipped because external commands cannot apply a file-age filter. Exits `1` on a malformed `DAYS` or when no eligible config target remains after skipping `action:*` rows. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--action-timeout SECONDS`**: With cleanup, stop each `action:*` command still running after `SECONDS` seconds (a non-negative decimal integer) with `timeout --kill-after=10`, print `Error: Action '<action>' for '<name>' timed out after SECONDS seconds.`, count the target as failed, and continue with the remaining targets and retention, so the run exits `1`. `0` or unset keeps actions unbounded; a positive limit in a cleanup run requires `timeout(1)`. Exits `1` on a malformed `SECONDS`. On a terminal the action runs in the foreground so Ctrl-C still reaches it; a timeout then signals only the action's own process (sudo passes it on), so a helper process the action started itself may outlive the limit. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--trash-keep-days DAYS`**: With cleanup, purge quarantine sessions older than `DAYS` days (a non-negative integer) at the end of a non-dry-run cleanup via `older-than:DAYS` retention (prompts for confirmation unless `-f/--force` is set, and exits `0` when no sessions match). A `--dry-run` purges nothing. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--doctor`, or `--only-path`.
- **`--list-targets`**: List configured targets (`NAME`, `risk`, `path`, `description`) without disk analysis. Supports `--only-target`, `--exclude-target`, `--only-path`, and `--exclude-path` with the same selection and empty-selection errors as cleanup; inventory includes all risk levels. Read-only; requires a config file. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--check-config`**: Validate config syntax and exit without disk analysis. Prints `OK: N targets in <path>`. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--init-config`**: Copy the active config to `${XDG_CONFIG_HOME:-$HOME/.config}/linux-cleaner/cleaner.conf` (mode `0644`, never overwriting an existing file or following symlinks) and exit. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--doctor`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--notify`, `--fail-fast`, or `--json`.
- **`--doctor`**: Print a read-only environment checklist (`OK`/`WARN`/`INFO` lines for the resolved configuration path and whether it came from `XDG`, `/etc`, `checkout`, or `explicit`, `check_gnu_userland`, `pgrep`, `flock`, `git`, non-interactive `sudo -n`, `notify-send`, `systemctl --user is-enabled` for the `clean`/`retention`/`monitor` timers, the last cleanup outcome, a `WARN` when the enabled clean timer's `~/.config/linux-cleaner/env` sets `LINUX_CLEANER_TRASH` with neither `LINUX_CLEANER_TRASH_KEEP_DAYS` nor an enabled retention timer, a `WARN` when `~/.config/linux-cleaner/monitor.env` is unreadable or sets both `LINUX_CLEANER_ONLY_PATH` and `LINUX_CLEANER_TRASH_KEEP_DAYS`, and the quarantine session count). Immediately after the timers, prints `INFO: last cleanup: <Saved> <Result>` using the header values from `${XDG_STATE_HOME:-$HOME/.local/state}/linux-cleaner/last-report.txt`, or `INFO: last cleanup: none recorded` when absent; symlinked reports or `linux-cleaner` state directories are not followed. Uses `WARN` when the result has `failed>0`, an `Interrupted:` line is present, a `Retention failed: true` line is present (appending `; retention failed`), or the clean timer is enabled and the report's modification time is more than two days old. An unreadable report prints `WARN: last cleanup: report not readable`. Last-cleanup warnings do not change the exit status. When the clean timer is enabled, also prints `INFO: daily timer plan: risk=<value|safe> deletion=<quarantine|permanent> keep-days=<N|none> [config=<path>] (<env path|no env file>)` from `~/.config/linux-cleaner/env`; without an env file it shows `risk=safe deletion=permanent keep-days=none (no env file)`. `config=` appears when the env file sets `LINUX_CLEANER_CONFIG`. The line uses `WARN` and appends `; invalid risk` when the env risk is not `safe`, `medium`, `danger` or `dangerous` (in any case), `; invalid keep-days` when `LINUX_CLEANER_TRASH_KEEP_DAYS` is not a non-negative integer, `; config not readable` when that config is not a readable file, `; config invalid` when it fails the schema check, or `; only-path with keep-days` when the file sets both `LINUX_CLEANER_ONLY_PATH` and `LINUX_CLEANER_TRASH_KEEP_DAYS`, which the clean run refuses. A relative `LINUX_CLEANER_CONFIG` is checked under `HOME`, where the user service starts; values are trimmed of surrounding whitespace, as systemd does. An env file that exists but cannot be read prints `WARN: daily timer plan: env file not readable (<path>)`, because systemd then fails every timer run. Disabled timers print no plan line. The retention warning and exit status are unchanged. A readable file is schema-checked; an invalid file prints `WARN: config: <path> (<source>, <error>)` and the rest of the checklist still prints. Exit `0` when cleanup can run or `1` when the configuration file is missing, unreadable, or invalid, or GNU userland is missing. Requires no configuration file to print the checklist. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--notify`, `--fail-fast`, or `--json`.
- **`--list-sessions`**: List quarantine sessions (timestamp, size, date, and each item's `full`/`aged` type and original path). Human output warns when immediate entries lack metadata accounting. JSON adds integer `unrecorded_entry_count` to every session, including zero; the `.hold` marker is not counted. A session protected by `--hold-session` ends its human line with `held`, and JSON `held` is `true` for it (`false` otherwise). Read/enumeration errors fail inventory and block purge before confirmation or deletion, including forced or inline retention. Counts are informational; zero does not certify metadata integrity, recoverability or safe purge. Read-only; requires no config file. Cannot be combined with `--restore`, `--purge-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--restore SESSION`**: Restore files from a quarantine session (`latest` or an immediate child timestamp directory name; `/` and `.`/`..` are rejected). Add `--dry-run` to preview selected records without taking the lock, invoking sudo, or changing payload, logs, metadata or session mtime. Prints `would restore`, `conflict`, `already restored`, `missing`, or `unknown type` (a record the real restore skips as failed), followed by two spaces and the original path; ends with `Dry-run: nothing restored.` and exits `0` even for conflicts or missing payload. Honours `--only` and `--only-exact`; an unmatched selector still exits `1`. Probes use the current user's access and do not guarantee permissions or free space for a later restore. Cannot be combined with `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--only PATTERN`**: Used with `--restore`: restore only targets whose original path contains `PATTERN`, keeping remaining targets and rewriting `quarantine.meta` so a later `--restore` succeeds. Exits `1` if nothing matches or if passed without `--restore`. Cannot combine with `--only-exact`; repeated `--only` uses the last value.
- **`--only-exact PATH`**: Used with `--restore`: select only records whose original path exactly equals nonempty literal `PATH`. Copy the path shown by `--list-sessions` (or its JSON `targets[].path`). The argument is not trimmed, expanded or normalized and need not be absolute or exist; there are no wildcard, descendant or comma-list semantics. Remaining records stay quarantined for a later restore. Exits `1` on no match or without `--restore`. Cannot combine with `--only` in either order; repeated `--only-exact` uses the last value. CLI-only, with no environment mirror.
- **`--purge-sessions SESSION`**: Permanently delete quarantine sessions (`latest`, `all`, `older-than:DAYS`, `max-size:SIZE`, `keep-latest:N`, or a timestamp directory name). Prompts for confirmation naming every target unless `-f/--force` is set. `older-than:DAYS`, `max-size:SIZE`, and `keep-latest:N` exit `0` when no sessions match (or when no quarantine directory exists). `max-size:SIZE` walks sessions newest-first using `du -sb` and purges every session once the running total exceeds `SIZE` (same integer and optional `K`/`M`/`G`/`T` 1024-based unit grammar as `--min-reclaim`). `keep-latest:N` lists sessions newest-first and purges every session after the first `N` (a decimal integer, N >= 1 (use all to purge everything)). An active explicit `--dry-run` prints the selected session names and sizes under a `Would purge` heading, plus notes for held sessions skipped by bulk selectors, and exits `0` without confirmation, deletion, a lock, or log/report writes, even with inherited `LINUX_CLEANER_FORCE`. Held sessions still count toward size/count limits; a held named or `latest` session is refused as in a real purge. A later `--clean`, `--force` or `--interactive` cancels the preview, so `--dry-run --force` purges. JSON is not supported, including for previews. Cannot be combined with `--restore`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--hold-session SESSION`**: Protect a quarantine session (`latest` or an immediate child timestamp directory name, validated like `--restore`) by writing a private `.hold` marker into it under the mutation lock; the session's mtime is left unchanged, so its retention age is not reset. Bulk purge selectors (`all`, `older-than:DAYS`, `max-size:SIZE`, `keep-latest:N`) and `--trash-keep-days` retention skip a held session with a `Skipping held session <name>` note, even with `-f/--force`; a held session still counts toward the `max-size` budget and the `keep-latest` count. Purging a held `latest` or named session exits `1` instead of picking another session. Any entry named `.hold` counts as a hold. A complete `--restore` removes the marker with the session; a partial restore keeps both. Holding a held session is a no-op. Cannot be combined with `--release-session`, `--restore`, `--purge-sessions`, `--list-sessions`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--doctor`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--notify`, `--fail-fast`, `--show-matches`, `--exit-code`, `--dry-run`, `--clean`, `--interactive`, or `--json`.
- **`--release-session SESSION`**: Remove the hold marker from a quarantine session (`latest` or a timestamp), so normal purge selectors and retention apply again based on the session's original mtime. Releasing an unheld session is a no-op. Cannot be combined with `--hold-session`, `--restore`, `--purge-sessions`, `--list-sessions`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, `--doctor`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--notify`, `--fail-fast`, `--show-matches`, `--exit-code`, `--dry-run`, `--clean`, `--interactive`, or `--json`.
- **`--report`**: Print the saved last cleanup report from `${XDG_STATE_HOME:-$HOME/.local/state}/linux-cleaner/last-report.txt` and exit (prints `No cleanup report yet.` on stderr and exits `1` if absent). With `--json`, emits a JSON object summarizing the saved report instead of the plain text (`saved`, `result`, `cleaned`, `skipped`, `failed`, `elapsed_seconds`, `failed_targets`, `quarantine_session`, `interrupted`, `retention_failed`, `quarantined_bytes`, `permanent_bytes`). Read-only; requires no config file. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--init-config`, or `--doctor`.
- **`--check-health SECONDS`**: Requires `--report`, with text or `--json`. Keep the normal report output, then exit `0` only if its file mtime is at most `SECONDS` old and the saved result succeeded; skipped targets, nothing-to-clean, minimum-reclaim and minimum-free skips count as success. Exit `1` with one reason line on stderr for missing, unreadable, symlinked, stale, future-dated, failed (`failed>0`), interrupted, retention-failed (`Retention failed: true`), or unrecognized reports, or if the age cannot be read. Accepts decimal integers `0..9223372036854775807`; leading zeros are normalized and repeated flags use the last value. CLI-only; no environment mirror, config requirement, timer dependency, or JSON schema change. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--init-config`, `--doctor`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, `--notify`, `--fail-fast`, `--show-matches`, or `--exit-code`.
- **`--log [FILE]`**: Append an operation log under `$HOME` (default: `~/.cache/linux-cleaner/operations.log`).
- **`-q, --quiet`**: Suppress headers, per-target status lines, and the on-screen plan report; keep errors, savings total, result report, and final summary.
- **`--debug`**: Show per-target `[FOUND]`, `[CLEAN]`, and `[PROTECTED]` lines (hidden by default; overridden by `--quiet`).
- **`--exit-code`**: In a text or JSON cleanup dry run, exit `2` when cleanup would run (`would_skip` is `null`), or `0` when below `--min-reclaim`, at/above `--min-free`, or there is nothing to clean. Errors still exit `1`. CLI-only (no environment mirror). The intentional status `2` emits no journal error priority line; the flag is omitted from the `Next:` command. Cannot be combined with `--clean`, `--force`, `--interactive` (even with a later `--dry-run`), `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`. Example: `cleaner --dry-run --quiet --min-reclaim 500M --exit-code`.
- **`--show-matches`**: In a text dry run, show per-target status lines and indent eligible paths below each found ordinary target. Directory listings apply the same age and exclusion predicates as cleanup; single files apply their age limit. Without age or exclusions, print only the target's own path. Skips `action:*` targets; `--quiet` suppresses the listing. CLI-only (no environment mirror). Cannot be combined with `--clean`, `--force`, `--interactive` (even with a later `--dry-run`), `--json`, `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`. Example: `cleaner --dry-run --show-matches --min-age 7 --exclude '*.log'`.
- **`--fail-fast`**: With cleanup, stop after the first failed target's accounting and log entry, before the next target, and skip inline `--trash-keep-days` retention even if the last target failed. Exit `1` and append `Stopped early: --fail-fast after <name>; <N> targets not attempted` to the printed and saved result report; N counts remaining targets in the cleanup loop. Safety skips and blocked targets do not trigger a stop. Without this modifier, cleanup and retention continue after target failures as before. Dry-run performs no cleanup and carries the flag in its `Next:` command. Notifications and metrics are unchanged. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--notify`**: With cleanup, send one desktop notification via `notify-send(1)` after inline retention summarizing the cleanup result (first line of the result report plus its `Reclaimed:` line, and any `Interrupted:` or `Retention failed: true` line; `--urgency=critical` when any target or inline retention failed or the run was interrupted). If an opted-in cleanup exits non-zero before reaching its result notification, sends one critical notification with `Cleanup stopped with exit status <N> before finishing; see journalctl --user -t linux-cleaner.`. No-op on `--dry-run`. Prints one warning on stderr when `--notify` is active and `notify-send` is absent; a missing binary, missing session bus, or failing or hanging notifier never changes the exit status. Cannot be combined with `--restore`, `--purge-sessions`, `--list-sessions`, `--hold-session`, `--release-session`, `--list-targets`, `--check-config`, `--report`, `--check-health`, `--init-config`, or `--doctor`.
- **`--json`**: Emit machine-readable JSON (implies `--quiet`). Valid only with `--dry-run` (`config`, `total_reclaimable_bytes`, `total_reclaimable_human`, `would_skip`, per-target `name`/`path`/`risk`/`bytes`/`size_human`/`status`/`description`/`min_age_days`/`size_at_run_time`/`reason`; top-level `would_skip` is `"skipped_below_min_reclaim"`, `"skipped_at_or_above_min_free"`, or `"nothing_to_clean"`, checked in that order, or `null` when cleanup would proceed; runtime-sized prune actions count as cleanable even at zero planned bytes; `size_at_run_time` is `true` for user-level prune actions, whose size is measured only when they run, and `reason` holds the skip or block reason, empty when none), `--list-targets` (`config`, per-target `name`/`risk`/`path`/`description`/`min_age_days`/`check_processes`/`custom_action`), `--list-sessions` (`sessions` array of `timestamp`/`size_bytes`/`size_human`/`date`/`unrecorded_entry_count`/`targets`), or `--report` (`saved`, `result` as `"completed"`/`"nothing_to_clean"`/`"skipped_below_min_reclaim"`/`"skipped_at_or_above_min_free"`, numeric `cleaned`/`skipped`/`failed`/`elapsed_seconds` or `null` when absent, `failed_targets` array, string-or-`null` `quarantine_session` and `interrupted`, the additive nullable `retention_failed` boolean, and nullable integer `quarantined_bytes`/`permanent_bytes`). `retention_failed` is `true` when inline retention failed, `false` when it did not fail (including cancellation), and `null` for historical reports, runs without retention, or retention interrupted before its outcome is known. The byte fields preserve exact existing accounted estimates, not guaranteed physical disk reclamation: ordinary targets and system actions credit planned sizes, while user prune actions credit nonnegative free-space deltas. New nothing-to-clean/minimum-reclaim/minimum-free skips record zero; historical or malformed byte records yield `null`. Interrupted runs include only already-credited work, retention volume is excluded, and cancellation before work preserves the previous report. Target counts and result meanings are unchanged. Consumers should tolerate unknown JSON keys for forward compatibility.
- **`--allow-outside-home`**: Deprecated no-op (prints one warning on stderr; targets outside `$HOME` are always allowed).
- **`-h, --help`**: Display help and exit.
- **`-V, --version`**: Print version and exit.

Value-taking options (`-c/--config`, `-r/--risk`, `-e/--exclude`, `--restore`, `--hold-session`, `--release-session`, `--only`, `--only-exact`, `--only-target`, `--exclude-target`, `--only-path`, `--exclude-path`, `--lock-wait`, `--check-health`, `--min-reclaim`, `--min-free`, `--min-free-path`, `--min-age`, `--action-timeout`, `--trash-keep-days`, and `--purge-sessions`) refuse a following long option (`--...`) or `-d` as their argument and exit `1` with `Error: <flag> requires a value, got option '<token>'.` before any analysis or deletion, so a missing value can never turn `--dry-run`/`-d` into a pattern. Other dash-leading values, such as `-x*` or a target `NAME` of `-n`, are still accepted.

## Exit status

With **`--exit-code`**, a text or JSON cleanup dry run returns **`2`** when cleanup would run, or **`0`** when a minimum-reclaim/free gate would skip it or there is nothing to clean; errors remain **`1`**. Without this modifier, successful previews return **`0`**.

Returns **`0`** on success, **`130` (`SIGINT`)** or **`143` (`SIGTERM`)** when a cleanup is interrupted by a signal, and **`1` (non-zero)** on a configuration/usage error, failure to acquire the mutation lock within the configured wait (default zero), including a concurrent mutating run holding `~/.cache/linux-cleaner/cleaner.lock` (`Error: another linux-cleaner run is in progress (lock: <path>).`), or a **failed operation** (an attempted delete, quarantine move, predefined action, restore, or session purge that did not succeed). When an operation fails during cleanup, `cleaner` reports the error on stderr, continues processing remaining targets, and exits `1`.

A **skip is not a failure** and exits **`0`**: a declined `danger` target, a target blocked by a running process, an `UNSAFE` or `protected` path, a git-tracked target, a root-requiring target when privileges are unavailable, or a predefined `action:*` whose package manager binary is not installed.
